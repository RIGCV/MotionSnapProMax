# 目录选择与本地保存修复验收（2026-11-18）

## 检查范围与结论

检查网页入口、目录辅助模块、PNG 编码、写入模块、Worker、模型配置、移动检测、跟踪、事件绑定、页面 DOM、部署脚本和现有测试。Python 桌面端与本次网页问题无关，未改动。

确认的代码问题：

- 上一版 picker 使用 `mode: read`，随后跨异步边界申请写入，与要求的直接 readwrite 选择流程不同，增加权限交互的不确定性。已改为点击内直接调用 readwrite picker，返回后只验证；补充授权仅由明确的授权按钮发起。
- 手动截图未经过自动截图的互斥锁。现两者共享同一锁，编码与写入均最多一个任务在途。
- 写入失败未可靠地撤销本地可写标记。现失败暂停自动保存、清除标记并保留错误，检测循环绝不申请权限。
- 停止与未结束写入的生命周期未统一。现停止立即关闭媒体轨道，编码中的旧帧不写入，已经开始的写入完成后计数；在途任务结束前不允许重启/换目录。
- 旧版 AbortError 提示曾误判取消。现只报告选择/授权未完成，记录原始异常及阶段，不将名称视为唯一原因。

未发现的疑因：按钮各绑定一次，没有重复监听器；picker 调用前没有 await、模型初始化、摄像头请求或定时器；并发选择锁已有并经回归测试；句柄保存在模块状态，不是易丢失的局部变量。旧代码中的这些部分不能作为用户 Edge 故障的已确认原因。

**尚不能确认用户机器上原生 AbortError 的底层唯一原因。** 文件夹普通、磁盘健康不能证明浏览器已授予权限。必须结合真实 Edge 的目录选择日志与授权结果继续定位，不能仅凭模拟测试宣布原生问题已解决。

- 摄像头申请未返回时禁止重复启动；停止或退出后迟到的媒体流立即停止。NotReadableError 提示不再断言一定是其他应用占用。
- index.html：新增“退出程序”按钮（释放资源后留在页面，浏览器手动打开的标签页不强制关闭）；提示改为“点击图片可直接下载当前截图”。
- app-harness.mjs、start-save.test.mjs：新增生命周期事件、迟到媒体流、播放失败与重试、退出时写入未结束的回归测试。
- npm test：26 项通过。新增验证使用媒体流/浏览器事件模拟，未进行本版真实摄像头占用、关闭浏览器或驱动层测试。
- 点击退出时当前写入可完成，摄像头立即释放；真正关闭页面后浏览器不保证异步文件写入完成。程序只在 close 成功后增加计数。网页只能释放自己持有的媒体流，不能释放其他应用或其他标签页的摄像头。

## 本机摄像头选择修复（2026-11-18）

用户截图显示浏览器默认设备提供 vivo 办公套件的手机连接占位画面。Windows Camera 设备列表确认 Chicony USB2.0 Camera 状态 OK。

新增 camera.js 根据已授权设备名称识别常见内置摄像头，排除 vivo、OBS、手机及常见虚拟设备与红外设备。main.js 以 exact deviceId 打开识别出的设备；没有识别结果时明确报错，不静默回退系统默认。首次授权前若名称被隐藏，临时授权流不展示、不推理，枚举后复用匹配流或先释放再切换；退出时仍释放迟到的流。

浏览器不提供通用的“物理内置”标记，因此名称识别有边界；未识别设备需补充名称规则，不能宣称所有厂商、所有外置或自定义命名设备均能准确分类。摄像头栏仅展示自动识别出的设备。
